# URL 与链接的本地化

> ## 硬规则：URL 在任何语言里都不译
>
> URL 不是文本，是**语言无关的标识符** —— 它标识一个资源，不表达意思。翻译它等于造出一个**不存在的地址**。
> 因此这条规则**没有语言例外、没有文体例外、没有「读起来更自然」的例外**：无论源语目标语是什么、文本多长、URL 里的单词多像该翻，都照原样保留。
>
> 但「不译」只回答了**不做什么**，没回答**要做什么**。把两者混为一谈，会同时犯两个方向的错：把该冻结的改坏，把该换的没换。

## 0. 先立规则，再讲例外

### 0.1 绝对禁止（无语言例外）

以下内容**不译、不改、不重排、不转换大小写**，与源语目标语是哪种语言无关：

- 协议、域名、端口、路径**资源标识段**（`/product/1234`、SKU、哈希 id）
- 查询参数**名**（`?color=`）与参数**值**（除非后端明确声明支持本地化值）
- `utm_*` / `gclid` / `fbclid` / `ref` 等追踪参数
- fragment（`#section-2`，多为页面内锚点 id）
- 邮箱地址、`mailto:` / `tel:` 的地址部分、IP 地址、文件路径

**这条规则优先级高于「行文自然」。** 哪怕 URL 里的路径是完整英文单词（`/running-shoes`、`/help/shipping-policy`），**看起来该翻也不翻** —— 它不是句子的一部分，是地址。

### 0.2 四种真实的翻车方式

| # | 翻车方式 | 例子 | 后果 |
| --- | --- | --- | --- |
| 1 | **顺手翻路径段** | `/running-shoes` → `/chaussures-de-course` | 404。**这是最常犯的一种** —— 路径由完整单词组成时，模型会把它当正文一起翻 |
| 2 | **「智能替换」** | 排版工具把 `-` 换成 `–`、把 `%20` 换成 `+` | 链接打不开；再编码一次变 `%2520` |
| 3 | **翻译或删除追踪参数** | `utm_source=newsletter` 被译 / 被「精简」掉 | 归因断链，投放数据对不上 |
| 4 | **href 与锚文本搞反** | 翻了 `<a href>` 里的地址，标签文字没翻 | 双错：链接坏 + 用户看不到译文 |

### 0.3 什么算「URL」：识别边界

判据是**「这段字符是否被当作地址使用」**，而不是「有没有 `http://`」：

| 形态 | 例 | 处理 |
| --- | --- | --- |
| 完整 URL | `https://shop.example.com/de/x?utm_source=…` | 冻结 |
| 无协议 | `www.example.com/x`、`example.com/x` | 冻结 |
| 裸域名 | `example.com` | 冻结 |
| 邮箱 / `mailto:` / `tel:` | `support@example.com`、`tel:+49…` | 地址冻结；`subject` / `body` 需本地化时**整体百分号编码** |
| IP 与端口 | `192.0.2.1:8080/x` | 冻结 |
| 文件路径 | `C:\Users\…`、`/etc/nginx/conf.d/`、`\\NAS\share` | 冻结 |
| 深链 / 短链 | `app://…`、`bit.ly/xxxx` | 冻结（是否换指向见 §3） |
| **嵌套 URL** | `?redirect=https%3A%2F%2Fexample.com%2Fx` | 冻结；**不要解码后再编码** —— 编码层级变了就是另一个值 |
| 位于受保护区 | 代码块、JSON、CSV、HTML 属性 | 结构不动，只改该改的文本（见 `engineering.md`） |
| 二维码 / 图片里的网址 | 印刷物、包装上的 QR | 字符虽不在文本层，**同样不译**；指向变了须重出图 |

### 0.4 三类动作分开看

「不译」不等于「什么都不做」。除冻结外还有两件事：

| 动作 | 对象 | 判定 |
| --- | --- | --- |
| **保留**（逐字符冻结） | 协议、域名、端口、资源标识段、参数名、追踪参数 | ✅ 不译不改，**一个字符都不动** |
| **本地化** | 路径目录段与 slug（`/running-shoes` → `/laufschuhe`） | ⚠️ 可做，但**不是硬规则**，且须**重新取词**（见 §2）。**默认不做** |
| **换指向** | 链接的目标站/目标语言版本 | ⚠️ **最常被漏**：有本地版本就该指本地版本（见 §3）。这是换链接，不是翻 URL |
| **排版处理** | 可见文本里的 URL | ✅ 字符不变，但 RTL / 换行 / 尾随标点必须处理（见 §5） |

一句话判据：**改「地址」= 禁止；改「读法」= 必须；换「指向」= 按策略。**

> **对「任何语言都不译」的准确表述**：冻结是绝对的（0.1）；**唯一允许 URL 字符发生变化的情形是「换指向」与「经确认的 slug 本地化」，两者都不是翻译，而是换一个已存在的地址**，且必须写进说明表与「待确认」。
> 除此之外 —— **任何语言、任何文体、任何理由，URL 一律逐字符保留。**

## 1. URL 组件拆解：哪一段能碰

RFC 3986 的通用语法：

```
scheme://userinfo@host:port/path?query#fragment
```

| 组件 | 示例 | 可否本地化 | 说明 |
| --- | --- | --- | --- |
| scheme | `https` | ❌ | RFC 3986 规定 scheme 与 host **大小写不敏感**，规范形式为小写 |
| host / 域名 | `shop.example.com` | ❌ 译名 | 国际域名的非 ASCII 部分用 punycode（`xn--` 前缀，如 `café.com` → `xn--caf-dma.com`）。**换 ccTLD 或子域属于策略决策，不是翻译** |
| port | `:443` | ❌ | 数字 |
| path 目录段 | `/de/laufschuhe` | ⚠️ 可 | 唯一可本地化的组件 |
| path 资源标识段 | `/product/1234`、`/p/aBcD9`、SKU | ❌ | 标识符，改了就是另一个资源 |
| query 参数**名** | `?color=` | ❌ | 后端契约，翻译即断链 |
| query 参数**值** | `?color=blue` | ❌（默认） | 除非后端明确支持本地化值，否则不动 |
| 追踪参数 | `utm_source` `gclid` `fbclid` `ref` | ❌ | 翻译或删除 = 断掉归因，且违反「不删减」原则 |
| fragment | `#section-2` | ❌ | 多数是页面内锚点 id |

**铁律**：URL 是**逐字符**的，不是逐词的。大小写不同（Linux 服务器与 GitHub Pages 大小写敏感）、多一个或差一个斜杠、连字符被替换 → **都是另一个地址**。大小写部分详见 `case-orthography.md`。

## 2. slug 要不要本地化：分情况，别一刀切

| | 支持本地化 | 谨慎 / 不做 |
| --- | --- | --- |
| 理由 | 本地用户与搜索引擎都更认；对可读性与点击率有帮助 | **非拉丁文字**（中日韩阿俄希）百分号编码后不可读 |
| 例 | 德站 `/de/laufschuhe` 优于 `/de/running-shoes` | `/zh/跑鞋` 编码成 `%E8%B7%91%E9%9E%8B`，在分享、分析报表、印刷物料里都是乱码 |
| 结论 | 拉丁字母语言：做了更好 | 非拉丁：**拉丁转写**或**保留英文 slug** 往往更务实（转写规则见 `engineering.md` §1.1） |

两条硬约束：

1. **slug 本地化 ≠ 把标题翻译一遍。** 它属于关键词层 —— 必须先按目标市场重新取词（`localization-checklist.md` §11），否则就是把一个错词换成另一个错词。
2. **改就必须配 301**，并同步更新：内链、`canonical`、`hreflang`、`sitemap`。少一样就会产生死链或重复内容。

> 业界对此并无统一答案：一派认为应当本地化 slug，一派认为保持稳定、可描述的结构优先。因此**本 skill 不替站点做决定** —— 默认**保留原文 URL**，把「是否本地化 slug」写进「待确认」。

## 3. 什么时候 URL 应该「换指向」（最容易被漏）

**这不是翻译 URL，是换一个链接。** 判断依据是：目标市场的读者点进去，能不能直接读到能用的内容。

| 场景 | 做法 |
| --- | --- |
| 目标市场有本地化站点 | 指向本地版本（`/de/…`、`de.example.com`、`example.de`），而不是英文原站 |
| 政策 / 帮助 / 售后 / 法规页 | 优先目标语版本；**只有英文版时保留原链，并在「待确认」标注「该页无目标语版本」** |
| App 深链与应用商店 | 换国家区（`apps.apple.com/de/app/…`、Play 的 `&gl=DE`）—— 不换会跳到错误国家区或提示不可用 |
| 活动 / 落地页 | 指向该市场的专属落地页，不要一律指向全球首页 |
| 官方文件（法规、认证证书、SDS） | 优先销售国官方语言、官方来源的页面或 PDF |
| 链接指向的内容本身是价格/型号 | 尤其要指向本地版本，否则币种、型号、库存全对不上 |

**不要做的两件事**（会让本地化站点自己把自己的收录搞坏）：

- ❌ 用 `?lang=xx` 参数做语言切换 —— 参数化语言版本在抓取与索引上不稳定，搜索引擎明确不推荐
- ❌ 按 IP 或 `Accept-Language` 自动跳转 —— 爬虫无法发现其他语言版本，且用户与爬虫看到的 URL 不一致

✅ 正确做法：**可点击的语言链接 + `hreflang` 标注**。

### hreflang 三条最容易错的

1. **每个语言版本必须自引用**（页面上要有指向自己的 `hreflang`），且各版本之间**必须双向互指**，缺一环整组可能失效
2. `hreflang` 里的 URL **必须是含协议的绝对 URL**（`https://…`，不能写 `/de/page`）
3. **语言码用 ISO 639-1，地区码用 ISO 3166-1 alpha-2**：`en-UK` 是**错的**（UK 不是合法地区码）→ `en-GB`；中文用 `zh-Hans` / `zh-Hant` 区分简繁；拉美西语用 `es-419`
4. 别忘 `x-default`（未匹配任何语言时的兜底页）

## 4. 逐字冻结清单（交付前核对）

- [ ] **不用任何工具「重排 / 美化 / 格式化」URL** —— 编辑器、Word、模型都可能自动改字符（把连字符换成 en dash、补上尾斜杠）
- [ ] 不补、不删结尾斜杠（服务端可能视为两个地址，跳转应由站点配置决定）
- [ ] 不对 URL 做 title case / 全大写 / 去重音 / 去变音符
- [ ] 不改大小写（见 `case-orthography.md`）
- [ ] **`%20` 保持 `%20`** —— 不换成 `+`（`+` 只在表单编码语境里代表空格），不双重编码（`%20` → `%2520`）
- [ ] 不翻译、不删除 `utm_*` / `gclid` / `fbclid` / `ref` 等追踪参数
- [ ] `mailto:` 的地址不译；若 `subject` / `body` 需本地化，**整体做百分号编码**（中文与变音符必须编码）
- [ ] 相对链接转绝对链接时**只补 base，不改路径**
- [ ] **href 不译，锚文本必须译**：`<a href="https://…/shipping">Read our shipping policy</a>` → 只改标签内文字

## 5. 可见 URL 的排版（字符没变，但会「显示错」）

这层不属翻译，但属于本地化交付质量 —— 且是**看起来错、复制下来才对**的那类问题。

- **RTL 隔离（最重要）**：URL、邮箱、文件路径出现在阿拉伯语 / 希伯来语 / 波斯语正文里时，若不做隔离，末尾的 `/` `?` `#` 会被双向算法重排到错误一端。做法：
  - ✅ 用 **LRI / RLI / FSI / PDI**（U+2066–U+2069）包裹，或直接给该片段 `dir="ltr"`
  - ❌ **不要用 RLE / LRE / PDF**（U+202A–U+202C）—— 自 Unicode 6.3 起已弃用（`locale-profiles.md` 已同步修正）
  - 纯视觉对齐问题可用 **LRM / RLM**（U+200E / U+200F）
- **长 URL 换行**：用 `<wbr>` 或 CSS `overflow-wrap` / `word-break`；**绝不用连字符 `-` 断行**（用户复制时会带上这个假连字符，链接直接打不开）
- **尾随标点**：LTR 语境下别让句末标点被吸进链接（必要时用 `<>` 包裹）；中文 / 日文里全角标点紧贴 URL 是正常的，**不要为此补空格**
- **连字符是 ASCII hyphen**：排版工具的「智能替换」会把 `-` 变成 `–`，直接弄坏链接 —— 交付前搜一遍
- **不要用 CSS `text-transform` 处理 URL 可见文本**：显示值与真实地址不一致，用户手抄就错（且土耳其语下 `i` → `I`）
- **显示可截断，复制值必须完整**：`example.com/…/product` 只是展示层，不许把截断值当成实际链接交出去

## 6. 链接文本与可访问性

- **锚文本要译，且要能独立读懂** —— 整页都是「点击这里」「了解更多」，屏幕阅读器用户无法判断去向。与原文风格冲突时以可用性优先，并在说明表写明
- `alt` / `aria-label` 里的链接说明同样要译
- **同一链接在同一页内只出现一种译法**（导航、页脚、正文里别各译一套）
- 语言切换器的入口文字用**目标语言自身**书写（de 站写 `Deutsch`，不要写 `德语`）—— 这是通行做法，方便不熟悉当前语言的用户找到出口

## 7. 交付时怎么写进输出

URL 相关处理统一进「关键处理说明」表：

| 原文 | 直译（不采用） | 终稿（采用） | 理由 |
| --- | --- | --- | --- |
| `https://example.com/running-shoes` | — | `https://example.com/de/laufschuhe` | slug 本地化（已确认站点结构与 301） |
| `https://example.com/shipping` | — | 保留原样 | 无目标语版本，指向英文页 |
| `utm_source=newsletter` | — | 保留原样 | 追踪参数，不译不改 |

**「待确认」必列**：

- 该市场是否存在对应本地版本可替换（不确定就别擅自替换）
- 若本地化了 slug：301、内链、`canonical`、`hreflang`、`sitemap` 是否已同步
- 追踪参数 / 深链是否需要按投放平台改写
- 政策类页面是否存在目标语版本

## 8. 交付前必做：URL 清单比对（客观验证）

这是唯一能**证明**「URL 一个都没被改」的做法，不依赖人眼，一分钟内完成，能挡住 §0.2 里的四种翻车。

**做法**：分别从源文本与译文里抽出所有 URL，排序后逐字符比对。

```bash
# 源文存 src.txt、译文存 tgt.txt
# 1) 抽取（ASCII 字符类 + 剥离句末标点，兼容各种 grep 实现）
grep -oE '(https?://|ftp://|www\.)[^[:space:]<>"]+' src.txt | sed 's/[.,;:!?、。，；]*$//' | sort > urls.src
grep -oE '(https?://|ftp://|www\.)[^[:space:]<>"]+' tgt.txt | sed 's/[.,;:!?、。，；]*$//' | sort > urls.tgt
# 2) 比对
diff urls.src urls.tgt && echo "✅ URL 完全一致"
```

> **命令的两个注意点**（实测踩过）：
> - **字符类只放 ASCII**。把全角标点（`，。「」`）写进 `[^…]` 会让部分 grep 实现（含 macOS BSD grep）**静默返回 0 匹配** —— 你以为「比对通过」，其实是根本没抽到东西。全角标点交给 `sed` 处理。
> - **`?` `&` `=` `%` 必须保留**（它们是 URL 的一部分）；`,;` 在 URL 里可以合法存在，这里为干净比对在句末截断，因两侧同样处理，结论仍然有效。若 URL 确实含逗号，改用 `[^[:space:]<>"]+` 并把句末标点差异当噪声看。
> - 未覆盖的形态（裸域名、邮箱、IP、文件路径）没有统一前缀，建议按 §0.3 清单**人工点一遍**，或用编辑器查找逐个确认。

命中差异时，逐条归类 —— **差异不等于译文错，但每一条都必须能解释**：

| diff 结果 | 判定 |
| --- | --- |
| 完全一致 | ✅ 通过 —— **但要先看 `urls.src` 是不是空文件**（0 匹配 = 假通过，见下） |
| 译文多出 / 少了 URL | 漏抄或多加 → **改回来** |
| 同一位置域名或路径不同 | 要么是**换指向**（正当，须写进说明表），要么是**被翻了**（退回） |
| 只差大小写 | **照样算错** —— 大小写敏感的服务器上是两个地址 |
| 多了 `%E…` 一串 | 被百分号编码了 → 退回（除非经确认，见 §2） |
| 仍残留句末标点 | `sed` 没剥干净（中文 `。` 等全角标点），非译文错误 |

> **最阴的失败模式：假通过。** 抽取命令若因环境差异没匹配到任何东西，`urls.src` 与 `urls.tgt` **都是空的，diff 也会「一致」**。
> 所以比对前**先确认源文件抽到了东西**：`wc -l urls.src` 应该等于原文里的 URL 数量。数量不对 → 命令没生效，不是没问题。

**肉眼最容易漏的字符**：`-` `_` `~` `.` `/` `%` 与大小写。比对时把 `-` 与 `–`、`/` 与 `\` 也一并盯住。

**没有 shell 环境时**：让模型「把源文里出现的所有 URL 原样列一遍，再把译文里的列一遍，两边对齐比较」，**这一步不能跳**。

**顺带查一遍**：`href` 数量与源文一致、锚文本已译、无被编辑器「智能替换」的连字符。

- [ ] 无协议地址 / 裸域名 / 邮箱 / IP / 文件路径 / 嵌套编码 URL 均已按 §0.3 冻结
- [ ] 所有 URL **逐字符**与原文一致（除经确认的 slug 本地化或换指向）
- [ ] 协议、域名、端口、查询参数名、追踪参数未被翻译或改动
- [ ] **href 未译，锚文本已译**
- [ ] 无双重编码、无 `%20` → `+`、无被「智能替换」成 en dash 的连字符
