# 大小写与正字法（case & orthography）

> 为什么单列一份：**「大小写」不是一个装饰选项，它在不同语系里承载的信息量完全不同。** 英文里 China 与 china 是两个词；中文里根本不存在这个维度；德语里名词不大写是拼写错误。
> 来源：知乎《盘点｜那些首字母大小写不同，意思千差万别的单词》引出的问题，本文件把它扩成可执行规则。

## 1. 先分三档：你的目标语属于哪一类

| 档 | 特征 | 语言 | 对本流水线的要求 |
| --- | --- | --- | --- |
| **A. 语义型** | 大小写改变词义 | 英语（最典型） | 大小写**必须逐词判断**，不能整体套 title case / lowercase |
| **B. 正字法型** | 大小写不改变词义，但有**强制拼写规则**，写错=错别字 | 德语、法语、西语等罗曼语、土耳其语、荷兰语、希腊语 | 大小写**必须符合目标语正字法**，照搬源语的惯例就是错 |
| **C. 无大小写型** | 字母无大小写之分 | 中文、日文、韩文、泰文、阿拉伯文 | 源语的「大小写区分」**无法用大小写承接**，必须改用**词汇手段**（见 §4） |

## 2. A 档：英语——首字母大小写改义的词（附电商场景影响）

| 小写 | 大写 | 电商场景里会怎么出事 |
| --- | --- | --- |
| china（瓷器） | China（中国） | 陶瓷类目 Listing 写 `china dinnerware` 语法上指瓷器没错，但产地表述段落极易混淆；品名与产地必须分行写清 |
| japan（漆器） | Japan（日本） | 同上；漆器/涂层类目 |
| turkey（火鸡） | Turkey（土耳其） | 食品/烤具类目；产地写错 = 清关申报不符 |
| pole（杆） | Pole（波兰人） | 帐篷/灯具杆件类目；写 `Pole` 会被当成国籍/产地 |
| polish（抛光剂、擦亮） | Polish（波兰的、波兰语） | **最经典的坑**：美甲抛光剂类目。`nail polish` 正确；但产地段落里的 `Polish` 指波兰，两者在搜索里无法区分（见 §3） |
| march / may / august | March / May / August | 月份。**排期、促销日历、上架时间**字段写错会直接错月份 |
| john（厕所，俚语） | John（人名） | 人名/品牌名，切勿套用到商品描述 |
| shanghai（诓骗，动词，旧俚语） | Shanghai（上海） | 品牌名与地名；该动词义已过时且带冒犯性，**不得在文案中使用** |

> 词源说法（如「先有 China 才有 china」、shanghai 的水手故事）**仅供了解，不要写进文案当事实**。

## 3. 搜索与平台：大小写**不能**用来区分词义

这条比词表本身更重要。

- **亚马逊、Google 等搜索引擎的匹配不区分大小写。** `polish` 与 `Polish` 在检索层是**同一个 token**。因此：
  - ❌ 不要指望「同时写入 polish 和 Polish」来覆盖「抛光」与「波兰」两个意图 —— 会被归一化视为**重复堆词**，无效且浪费字符
  - ✅ 必须用**上下文词组**消歧：`nail polish` / `polish remover`（品）vs `made in Poland` / `Polish brand`（产地）
- **大小写错误不影响搜索命中，但影响观感。** Listing 标题里该大写的国家名写小写（`made in china`），当地买家一眼看出不是本国人写的 —— 这是最廉价的「机翻痕迹」。
- **确实区分大小写的界面**（必须逐字核对，错一个字就失效）：

| 界面 | 风险 |
| --- | --- |
| URL / slug / 文件路径 | Linux 服务器与 GitHub Pages **大小写敏感**：`/Nail-Polish` 与 `/nail-polish` 是两个页面 → 404 或重复内容 |
| 语言码（BCP 47） | 规范写法 `en-US`、`zh-Hans-CN`、`pt-BR`（地区大写、脚本首字母大写）；`en-us`、`ZH-cn` 不规范 |
| SKU / 型号 / 优惠码 / ASIN / 追踪参数 | 属**禁改项**，大小写逐字保留 |
| 数据库排序规则 | MySQL 默认 `_ci` 不敏感，但 `utf8mb4_bin` / `_as_cs` **敏感** —— 站内搜索若建了敏感索引，大小写不符会漏命中 |

## 4. B / C 档：各语系的正字法惯例对照

**照搬源语惯例就是错**，这是最隐蔽的一类本地化失误。

| 语言 | 国籍 / 语言词 | 月份 / 星期 | 其他必须知道 |
| --- | --- | --- | --- |
| **en** 英/美 | **大写** Polish, English | **大写** March, Monday | A 档，见 §2 |
| **de** 德 | **小写** `polnisch`、`deutsch`（形容词）；作名词才大写 `der Pole`、`der Deutsche` | **大写** `Januar`、`Montag` | **所有名词一律大写**（语法要求），名词写小写=错别字；复合词整体大写首字母 |
| **fr** 法 | **小写** `polonais`、`français`（形容词）；名词 `un Polonais` 大写 | **小写** `janvier`、`lundi` | `État`（国家/政权）vs `état`（状态）；`Dieu` vs `dieu` |
| **es** 西 | **小写** `polaco`、`español` | **小写** `enero`、`lunes` | 与法语同规律 |
| **it** 意 | 小写 `polacco`、`italiano` | 小写 `gennaio`、`lunedì` | 同上 |
| **pt** 葡 | 小写 `polonês`、`português` | 小写 `janeiro`、`segunda-feira` | 同上 |
| **nl** 荷 | 小写 `Pools`→`pools` | 小写 `januari`、`maandag` | **IJ 连字**：词首两个字母都大写 `IJsselmeer`；全大写时 `IJSSELMEER` |
| **tr** 土 | **大写** `Türk`、`İngilizce`、`Almanca`（**与英语同，不像其他欧洲语言**） | **小写** `pazartesi`、`ocak`；但**固定日期与节日**中大写 `19 Ocak Salı`、`Cumhuriyet Bayramı` | `i/ı` 与 `İ/I`：`I`.toLowerCase() ≠ `i`（应为 `ı`），需 locale-aware 转换 |
| **lt / lv** | 小写 `lietuvis`、`anglų` | 小写 `pirmadienis`、`spalis` | 立陶宛排序特殊：`Y` 排在 `Į` 与 `J` 之间 |
| **ru** 俄 | 小写 `польский` | 小写 `январь`、`понедельник` | 西里尔字母大小写转换同样有坑 |
| **el** 希 | — | — | **全大写时丢重音**（`Ά`→`Α`）；词尾 sigma `ς`（小写词尾）vs `σ` |
| **zh / ja / ko** | **无大小写** | **无** | 见 §4.1 |

### 4.1 C 档语言：用词汇手段承接「大小写区分」

中文/日文/韩文没有大小写，因此英文靠大小写区分的东西，在这些语言里**必须换用不同的词**：

| 英文 | 中文处理 | 日文处理 |
| --- | --- | --- |
| china / China | 瓷器 / 中国 | 磁器 / 中国 |
| polish / Polish | 抛光剂 / 波兰的 | ポリッシュ / ポーランドの |
| turkey / Turkey | 火鸡 / 土耳其 | 七面鳥 / トルコ |
| march / March | 游行 / 三月 | デモ行進 / 3月 |

同理，日语还用**假名与汉字的选择**承载类似信息（`カタカナ` 多用于外来语、`ひらがな` 更柔和、汉字更正式）；中文则用**全角/半角**承担一部分「形式要正确」的压力。这些都不是可以随意替换的装饰。

## 5. 会被系统强制改大小写的环节（改了就丢信息）

| 环节 | 后果 | 处理 |
| --- | --- | --- |
| Title Case 函数、CSS `text-transform: capitalize` | `polish` → `Polish`，词义改变 | **不要对关键词/多义词列表做整体 title case** |
| CSS `text-transform: uppercase` + 土耳其语 | `i` → `I`，正确应为 `İ` | 给元素加 `lang="tr"`（浏览器才会用土耳其规则） |
| 全大写（营销强调风格） | 德文 `ß` → `SS`（长度 +1）；希腊文丢重音；法文重音常被实现丢弃 | 排版做全大写前，先确认目标语是否允许；德语全大写标题可用但读起来像机翻 |
| 全小写 | 任意 B 档语言的正字法被破坏 | 德语、法语等**绝不要**对正文做全小写处理 |
| 首字母大写（`.title()` 类） | 德语/法语把介词、冠词也大写 | 按目标语标题规范处理，别套英文 Title Case |

## 6. 品牌名与商标

- 品牌/产品名若与常用词同形（`Pole`、`August`、`May`、`John`、`China` 类），**大小写是文字上唯一的区分手段**，属于禁改项，全链路（Listing、包装、URL、SKU）必须一致
- 进入新市场前核对：是否与当地常用词同形、当地是否已有同名注册、是否需要转写（日文片假名等）
- 品牌 slogan 通常**不直译**，需要重新创作

## 7. 自检

- [ ] 目标语属于 A/B/C 哪一档已判定，并按对应规则处理
- [ ] 若为 B 档：国籍词、月份星期、名词大写是否符合**目标语**惯例（而非照搬源语）
- [ ] 若为 C 档：源语靠大小写区分的词，是否已用**不同的词**表达
- [ ] 关键词中的多义词是否用**上下文词组**消歧，而不是靠大小写
- [ ] 没有对关键词/多义词列表做过整体 title case / lowercase / uppercase
- [ ] URL、slug、语言码、SKU、优惠码的大小写已逐字核对（且语言码符合 BCP 47 规范写法）
- [ ] 品牌名与产品名的大小写全链路一致

> 本文件中的语言惯例为**通行规则**；个别出版物与品牌自有风格指南（style guide）可能另有规定，以目标市场的权威词典与品牌风格指南为准。
