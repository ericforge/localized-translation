# 目标市场语言档（locale-profiles）

R3「本土化编辑」开工前，先在这里查目标 locale 的特性。表中「默认敬语」为电商场景建议值，仍以品牌调性为准。

> **说明**
> - 「复数」列只作方向提示；实际类别必须以项目锁定的 CLDR / ICU 版本为准。`other` 是 ICU plural 的必需分支，其他类别按文案需要补充。
> - 「长度 vs 英文」是**经验区间，非承诺值**，最终以实测为准。
> - 语言代码按 **BCP 47**（地区用 `en-GB` 而非 `en-UK`）。

## 重点提示

### 德语 de-DE
- 名词全部大写，形容词变性数格
- 复合词连写可极长（如 `Produktsicherheitsinformationen`），**标题极易超亚马逊 200 字符**，需压缩
- 小数点用逗号、千分位用点：`1.299,00 €`
- **瑞士（de-CH）是例外**：千分位用撇号、小数点用点 → `CHF 1'299.00`。别把德国格式套到瑞士
- 敬语 Sie/du 混用是最明显的外行痕迹；DTC 年轻品牌可选 du，但要全站一致
- 说明书类目对「必须 / 应 / 建议」的措辞有法律含义

### 日语 ja-JP
- 敬语三层：尊敬語 / 謙譲語 / 丁寧語。电商卖点文案默认 `です・ます`，标题可体言止（名词结句）
- 外来语用片假名，同一英文词可能有多个通行写法（如 `スマートフォン` vs `スマホ`），需统一
- 全角标点；英数可用半角或全角，按品牌规范统一
- 药机法对化妆品「美白 / シワ改善」等功效宣称有严格分级
- 日期：`2026年9月23日` 或 `2026/09/23`；亦可用令和（令和8年）

### 阿拉伯语 ar
- **RTL 需按组件设计镜像，不是机械地把所有元素反转**：阅读顺序、导航和适合方向性的控件通常镜像；品牌图形、媒体内容、地图、数字图表和方向语义图标须逐项判断。**数字、拉丁品牌名、URL 不翻转**，需用 bidi **隔离符 LRI / RLI / FSI / PDI**（U+2066–2069，或给该片段 `dir="ltr"`）。新内容优先使用 isolates；不要新增 RLE / LRE / PDF（U+202A–U+202C）来包裹文本，旧内容是否替换需按渲染兼容性测试；纯视觉对齐才用 LRM / RLM（U+200E / U+200F）
- 阿拉伯语常见 6 个类别（zero/one/two/few/many/other）；按项目锁定的 CLDR/ICU 版本和实际消息覆盖需要的分支，并保留 `other` 回退
- 数字体系：多数中东站用西阿拉伯数字（123），沙特可选阿拉伯-印地数字（١٢٣）
- 方言差异极大（埃及、海湾、黎凡特），**电商默认用 MSA（现代标准阿拉伯语）**
- 宗教与文化保守：酒类、暴露服饰、部分图案禁用

### 希伯来语 he / 波斯语 fa
- 同 RTL 规则；希伯来语无元音符号，同形词需靠上下文
- 希伯来语复数含 dual 形式

### 中文 zh
- 简体（zh-CN / zh-SG）与繁体（zh-TW / zh-HK）**不可混**
- 台湾用词：軟體、行動電話、品質、網路；大陆：软件、手机、质量、网络
- 广告法极限词是硬红线（国家级、最佳、第一、根治、纯天然、无副作用等）
- 全角标点；中英混排空格依项目规范

### 泰语 th / 越南语 vi
- 泰语词间无空格，换行需分词；元音与声调符号为组合字符，**编辑时勿拆散**
- 泰文数字与佛历年（2026 → 2569）
- 越南语声调符号易在转码中丢失，输出后需肉眼核对
- 越南语人称常用亲属称谓（anh / chị / em），需按受众调整

### 西语 es —— 地区差异最被低估
- `es-ES`：ordenador、móvil、coche、vale、guay
- `es-MX`：computadora、celular、carro/auto、órale
- 拉美各国还有本地词（阿根廷 `vos tenés` voseo、哥伦比亚 `parce`、智利 `weón` 慎用于正式文案）
- **做墨西哥站别直接拿西班牙稿用**

### 葡语 pt
- pt-BR 与 pt-PT 差异覆盖拼写、词汇、语法（如 PT 用 `ecrã` vs BR `tela`；PT `equipa` vs BR `time`；PT `casa de banho` vs BR `banheiro`）
- 巴西是拉美最大市场，默认 pt-BR

### 土耳其语 tr
- `i / ı` 与 `İ / I` 的大小写转换是**经典编码 bug**（`I`.toLowerCase() ≠ `i`），涉及大小写转换的模板要测试
- 语序 SOV，长句重组幅度大

### 俄语 ru 与乌克兰语 uk
- 复数按末位数字分档（1 / 2-4 / 5-0），且 11-14 归入 many
- 西里尔字体与编码确认；勿与乌克兰语混用（政治敏感）

## 大小写：别按英语的习惯推

**国籍词、语言词、月份、星期该不该大写，各语系完全不同。** 必须按词性和语言分别判断，不能概括成“罗曼语国籍词全部小写”：

| | 国籍/语言词 | 月份/星期 |
| --- | --- | --- |
| **英语**（en-US/GB） | 大写 `Polish`、`English` | 大写 `March`、`Monday` |
| **德语** | **小写** `polnisch`、`deutsch`（作名词才大写） | 大写 `Januar`、`Montag`；**名词一律大写** |
| **法/西/意/葡** | **小写** `polonais`、`polaco` | **小写** `janvier`、`enero` |
| **土耳其语** | **大写** `Türk`、`İngilizce`（与英语同） | **小写** `pazartesi`、`ocak`（但固定日期 `19 Ocak` 大写） |
| **立陶宛/拉脱维亚** | 小写 | 小写 |
| **中文/日文/韩文** | **无大小写** —— 靠换词表达 | 无 |

完整规则（含「大小写改词义」的英语词表、搜索不区分大小写、title case 破坏词义、URL/SKU 大小写敏感）见 **`case-orthography.md`**。

## 何时启用 pivot（中转翻译）

- 默认禁止
- 仅在源语↔目标语资源极稀缺、直出质量明显不可用时启用，且需用户同意
- 反例说明：**英↔德/法/西/日** 这类高资源对**没有理由 pivot**；而**小语种之间**（如 越南语↔波兰语）若直出质量明显更差，pivot 经英文可能反而更稳 —— 判断依据是**实测质量**，不是教条
- 启用后必须：标注风险、核对关键术语与数字、对核心卖点句做回译验证

## 回译验证（back-translation）

对以下类型建议做：
- 高价值 Listing 的标题与首条卖点
- 合规与警示语
- 含数字、单位、价格、法律表述的段落
- pivot 产出的全部关键句

做法：把终稿回译成源语 → 与原文比对 → 有偏差的列出并判断是「合理本地化」还是「语义丢失」。
