# 工程交付层：语言包、代码、多语言站点

> 当交付物不是「一段文案」，而是**语言包 / JSON / 代码 / 多语言站点 / App** 时，额外过这一份。纯文案交付（Listing、邮件、说明书）可跳过。

## 1. 文件格式与处理原则

| 格式 | 关键注意 |
| --- | --- |
| JSON（i18n 语言包） | 只翻 value，**key 不动**；保留转义 `\"` `\\` `\n`；不得改嵌套结构；`zh-CN.json` / `en-US.json` 文件名按 BCP 47 |
| YAML | 保留缩进与引号风格；注意 `:` 后必须空格，翻译后容易破坏 |
| PO / gettext | `msgid` 不动，只填 `msgstr`；保留 `#:` 注释行；注意 `msgctxt` |
| XLIFF | `<source>` 不动，填 `<target>`；保留 `state` 与 `note` 属性 |
| ARB（Flutter） | 注意 `@key` 的 metadata 块 |
| CSV / XLSX | 只改译文列；不要重排行列；保留列头；注意带引号字段里的逗号。**分隔符随 locale 变**：欧洲/法语/德语 Excel 因逗号是小数点，导出 CSV 用**分号 `;`**，程序按逗号解析会整列错位 —— 收发前先确认分隔符与编码 |
| Android strings.xml | 转义与占位符规则特殊（`%1$s`、`\'`） |
| iOS .strings / .stringsdict | plurals 需按 `.stringsdict` 结构分支 |
| subtitle（SRT/VTT） | 保留时间轴编号；每行字符数受屏幕限制 |

**通用铁律**：先**复制源文件**再改；改完做一次 diff，确认**只有 value 变化**，key、结构、转义无一变动。

### 1.1 文件名、URL slug 与标识符的转写

非拉丁文字或带变音符的标题生成文件名/slug 时，转写规则**不止一套**，选错会产生拼写错误或搜不到的 URL：

| 来源 | 常见转写 | 注意 |
| --- | --- | --- |
| 德语 | `ü→ue`、`ö→oe`、`ä→ae`、`ß→ss` | 用 `u/o/a` 丢变音是**错拼** |
| 法语 | `é→e`、`è→e`、`ç→c` | 去音符可接受 |
| 丹麦/挪威 | `ø→oe`、`å→aa` 或 `a` | 两种做法都有，按当地惯例 |
| 中日韩 | 罗马字 / 拼音 | 日语 **Hepburn vs Kunrei-shiki** 不同（`し`→`shi` / `si`）；中文**拼音 vs 威妥玛**（`北京`→`Beijing` / `Peking`）—— 地名以**官方现行拼写**为准 |
| 阿拉伯/希伯来 | 多种体系 | 差异极大，建议直接用原文或人工确认 |

配套规则：slug 全小写、空格转 `-`、去掉重音后**仍要能被人读出来**；同一实体的 slug 全站一致；变更 slug 必须配 301 跳转。

> slug 该不该本地化、href 与锚文本如何分工、何时该换指向本地版本，见 `urls-and-links.md`。

## 2. ICU MessageFormat 与复数

- 复数不要用 `if/else` 手写，用 ICU：
  ```
  {count, plural, one {# item} other {# items}}
  ```
- **按目标 locale 补齐其 CLDR 全部类别**（俄语 4 类、阿拉伯语 6 类），缺类别会在运行时回退到 `other` 或直接报错
- 支持 `select`（性别）、`selectordinal`（序数）、`=0` 精确匹配
- 嵌套时保持括号配对；**翻译后必须用 ICU 解析器校验一次**
- 若项目用 i18next / vue-i18n / ICU，各自的复数键名不同（`_one` / `_other`），要对齐框架约定

## 3. 占位符与标签保护

- **绝不翻译**：`{name}` `{{name}}` `%s` `%d` `%1$s` `%{var}` `$t(key)` `<b>` `<br/>` `\n`
- 语序变化时必须用**带编号**的参数（`%1$s` 而不是 `%s`），否则英文的 `A of B` 翻成日语的 `B の A` 会错位
- 数量与顺序一致性要**机器校验**，不要靠肉眼
- **禁止字符串拼接**：`"You have " + n + " items"` 在多数语言里语法不成立。要拼就必须整句作为一条可翻译字符串
- HTML/富文本标签：保留标签名与属性，不要翻译 `class` / `id` / `href`（URL 本身的处理规则见 `urls-and-links.md`：**href 不译，但锚文本必须译**）

## 4. 编码与字符

- 统一 **UTF-8（不加 BOM）**；确认构建链没把 BOM 带进去
- 换行符：源码 LF，Windows 侧注意 CRLF 差异造成的假 diff
- **CJK 字符 UTF-8 占 3 字节**；emoji 与部分扩展区占 4 字节 —— 按**字节**限制的字段（如亚马逊 Search Terms 250 字节）不能按字符数估算
- 组合字符（泰文元音声调、天城文、阿拉伯语变音符）**不要按字符切分**，会拆散字形
- **大小写转换的坑**（用代码做 upper/lower 时）：
  - 土耳其语：`I`.toLowerCase() ≠ `i`（应为 `ı`），需用 locale-aware 转换；CSS `text-transform: uppercase` 同理要加 `lang="tr"`
  - 德语 `ß` 大写为 `SS`（长度 +1）
  - 希腊语词尾 sigma：`σ` vs `ς`；**全大写会丢重音**（`Ά`→`Α`）
  - 立陶宛语排序特殊（`Y` 排在 `Į` 与 `J` 之间），涉及排序时勿用二进制序
- **不要对关键词或多义词列表批量套 title case / lowercase** —— 英语里 `polish`（抛光）与 `Polish`（波兰的）是两个词，函数一改词义就变了。各语系的大小写惯例差异见 `case-orthography.md`
- 排序（collation）不要用默认二进制序：德语 `ö` 与 `o`、瑞典语 `å/ä/ö` 排在 `z` 之后、西班牙语历史上有独立 `ñ`

## 5. 长度、布局与伪本地化

- 用**伪本地化**（pseudolocalization）提前暴露问题：把源文替换成带重音与加长括号的伪字符串（如 `[!!! Ţēšţ !!!]`），能一次性暴露截断、硬编码宽度、未抽取的字符串
- 按钮、Tab、标签、Toast 都需要按最长语言预留；德文常是压垮布局的第一名
- 图片内文字、图标、箭头方向随 RTL 镜像
- 输入框要给欧式逗号小数留位置（`1.234,56` 比 `1,234.56` 长）

## 6. 交付前机器校验清单

能脚本化的别靠人眼：

- [ ] 占位符 / 参数集合与源文**完全一致**（数量、名称、顺序）
- [ ] 所有 key 都有译文，无遗漏、无多余
- [ ] 复数类别按目标 locale 补齐
- [ ] 字段长度/字节数未超限
- [ ] 文件编码 UTF-8 无 BOM；换行符一致
- [ ] 结构 diff 只落在 value
- [ ] ICU / 框架语法解析通过
- [ ] 无残留源语言片段（漏译检测）
- [ ] 无重复相邻词、无未闭合标签

## 7. 增量翻译与一致性

- 源文更新后，**只翻变更部分**，其余沿用已有译文；用版本控制记录每次源文与译文的对应关系
- 术语表（glossary）优先于模型自由发挥；同一术语跨语言包必须一致
- 建议保留一份 `glossary.md`（源词 | locale | 译文 | 品类 | 备注），每批追加

## 8. 质量评估口径（LQA / MQM 简版）

需要给译文打分时，按错误类型分级，比笼统说「质量好」有用：

| 类别 | 例子 |
| --- | --- |
| 准确性 | 误译、漏译、增译、语义反转 |
| 语言质量 | 语法错误、搭配不当、标点错误、术语不一致 |
| 风格 | 语域不符（敬语错档）、文体不统一 |
| 合规 | 违禁词、宣称超范围、缺强制要素 |
| 格式 | 占位符错误、标签破坏、超长、编码问题 |

严重度建议：**Critical（导致误解或违规）> Major（影响理解）> Minor（瑕疵）**。Critical 必须清零才交付。
